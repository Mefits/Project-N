# N Animation Director v1

## Mandate
N is a side-view 2D anime fighter (Godot 4.4.1, fixed simulation 120 Hz). The creative target is the speed, clarity and choreography of Naruto Ultimate Ninja Storm, not an exact copy. The owner reviews on a phone; do not require manual keyframing, art production or local editor work from them. Work on one motion family per checkpoint. The current priority is animation, not new combat features. PixelFX and hand signs are deferred until explicitly reprioritized.

Verified baseline: 0.10.1, e16ff0a7fa74306c4282773cbfff5e6309f896d3. Ground/air strings, seven confirmed contacts, defenses and knockdown must remain usable. Preserve the existing bounded hybrid spring reaction and smooth skin unless a measured defect requires a targeted change. No asset/style replacement, broad physics rewrite or 3D game conversion without approval.

## Work loop (mandatory)
1. **Diagnose.** Read the exact current code and last checkpoint. Render or inspect the previous real-engine clip at native speed and in frame sheets. Choose ONE observable defect; name its likely cause (timing, pose, support, root motion, blend, depth, deformation or contact). Do not confuse speculation with evidence.
2. **Reference.** Choose one primary movement reference and at most one stylistic reference for this task. Record URL/file, license or reference-only status, source FPS/timebase if known, exact time range, and observed events. Never invent timings or claim to have watched inaccessible footage. If reference cannot be inspected, use a clearly labeled authored hypothesis and report the limitation. See references/INDEX.md only for the relevant task.
3. **Plan poses and beats.** Before editing, write a small pose/timing sheet: frame or tick, ms, root/pelvis, chest/shoulders, head, support, knee/elbow, hand/foot target, contact or release, transition intent. Establish extremes and silhouette first. Distinguish measured source timing from proposed N timing. Use separate joint/channel curves or offsets where needed; do not make every joint share a single smoothstep. Keep attack gameplay windows explicit.
4. **Implement.** Start with pose data, then transition and support constraints, then secondary motion if necessary. Preserve old baseline for A/B. Do not use cosmetic effects to hide problems; no artificial hit radius inflation, root teleport, forced success, or broad game speed multiplier. Preserve input buffer, hitstop, real swept contact, mirror behavior and physics/render separation. Changes to hit timing or movement speed require explanation and regression tests.
5. **Measure.** Use fixed-step traces of root, hips, chest, head, shoulders, elbows, hands, knees, ankles and support state; facing, action age, contact and hitstop. Compare baseline and candidate with identical inputs. Check finite points, bone length, floor and support drift, trajectory discontinuities, phase durations, contact and exit state. Measure cadence, stride, flight/support fractions for locomotion; preparation, peak velocity, contact, follow-through, cancel and recovery for strikes. Normalize comparisons by character height where useful. Thresholds must be declared and justified by the current rig or reference; never silently weaken them to pass. Intentional snap is not the same as a discontinuity.
6. **Critique.** Separate visual-review pass after implementation; if a separate agent is available use it, otherwise explicitly perform a second pass against the checklist. Review real engine PNGs/contact sheet plus real-time GIF (slow version optionally labeled). Compare at identical scale, viewpoint, input, camera and timebase, retain full relevant movement in crop. Judge silhouette, timing contrast, weight, lead/lag, arcs, balance, contact and transition. Tests passing is not artistic approval. If visual review fails, revise or mark candidate provisional and retain the baseline.
7. **Deliver.** Commit one coherent milestone, run existing and new targeted regressions, record exact SHA, test status and artifacts. Send phone-friendly A/B GIFs, measured changes and remaining defects, not a wall of reports. Never claim capture or successful run without checking it. No future/background promises.

## Motion-specific checks
- Idle: asymmetry, planted feet, subtle weight transfer and breathing; head/arms must not move as a rigid block. Distinct guard vs idle.
- Walk/run: compare contact, compression, passing, push-off, swing and running flight. Opposed limb motion and hip/shoulder timing; root travel and stride agree. Ankle target stability alone is insufficient: inspect rendered feet and toe/heel clearance. Existing fixed shoe direction is a known limitation. Distinguish gait-only flight from real airborne physics. Test starts, stops, reversal, interrupted step.
- Jump/land: preparation, push-off, apex silhouette, descent, compression, rebound; avoid symmetric floating. Test short and moving transitions.
- Attacks: readable preparation, fast delivery, visible real contact, follow-through and recover. Whole-body kinetic sequence, not just moving a fist. Different hands and directions have distinct silhouettes. Keep intended hit/cancel windows, test hit/miss/block/parry/interruption. 120 ticks/s = 8.333 ms/tick; 60 fps reference frames = 2 ticks, 30 fps = 4 ticks, only when source timebase verified. No universal startup target.
- Combos: blend from actual outgoing pose/velocity, not neutral; preserve spacing, intentional hitstop and player input; validate all existing branches and mirror. Air: distinct pursuit, two strikes, downward finish, gravity and recovery; inspect attacker and victim together.
- Knockdown/get-up: use staged limb/hip motion and visible support instead of rotating an otherwise rigid whole skeleton; keep floor clearance, no slide/teleport, clear moment when controls return. Existing 0.10.1 rigid rotation is a baseline limitation.

## Retarget experiment (0.10.3 only)
Use one locally available, rights-cleared BVH or equivalent clip; prefer running for first test. Save source credit and license, source frame time, axes, scale and skeleton mapping. Parse hierarchy + ordered rotation channels and compute forward kinematics, check root convention and sample times. Derive projected joint targets, gait events and relative timings; separate root travel from game motor. Map left/right to N near/far and project into fight plane. Direct projection can collapse segment lengths; preserve N's IK lengths and use projection as direction/target guidance, with explicit treatment of depth and foreshortening. Compare original source, unstyled transfer and stylized candidate; do not claim raw Mocap equals anime quality. If data unavailable or retarget fails, keep original animation and diagnose. No external runtime service dependency or replacement of all animations in one pass.
